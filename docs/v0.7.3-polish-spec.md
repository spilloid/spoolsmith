# v0.7.3 — UX pass + bulk driver export

Operator direction, 2026-09-18. Astra (Codex `gpt-6-astra`, read-only, high
reasoning effort) ran a UX pass over the CLI and desktop GUI, primed with
`corporate-strategy/state/products/SpoolSmith.md` so its recommendations
stayed inside the actual authorization (milestone-authorized experiment,
Windows-only, no RMM/cloud, the D-0040 confirmation gate never weakened).
The operator separately spotted two GUI issues astra's source-only read
missed, and asked for bulk driver export, scoped out of the original
milestone for no recorded reason. This is a documentation/UX/CLI-ergonomics
release — it does not touch OS-mutation logic, the driver-payload trust
model, or the confirmation gate itself.

## Scope

**A. Astra's ranked findings (all ten, plus the parity-table follow-ups).**
See `docs/dev-process.md`'s log entry for this release for the full list and
verification notes; each is copy/help-text/consistency-only.

**B. Confirm-button caption.** `cmd/spoolsmith-gui/review_windows.go`
unconditionally appends `"..."` to `operation.Title()`'s already-clean
imperative text ("Add printer", "Update printer", "Remove printer", "Add
printer from file", "Change address"). Per Windows UI convention a trailing
ellipsis signals "opens another dialog," which is exactly the confusion the
operator flagged: the button performs the action immediately, it doesn't
open a menu. Fix: drop the suffix. Updates five hardcoded FlaUI assertions in
`test/gui/SpoolSmithGui.Tests/FunctionalTests.cs` that match on the old
caption strings.

**C. Offline terminology.** Two inconsistent labels exist today: the main
review checkbox (`cmd/spoolsmith-gui/main_windows.go`) never uses the word
"offline" at all, while the Intune wizard's checkbox
(`cmd/spoolsmith-gui/intune_windows.go`) uses jargon ("skip live identity
validation") inconsistent with it. Standardize on **"Offline setup"** as one
defined term — matching README's existing "Offline provisioning" section —
used as a short prefix on both checkboxes, keeping plain-language
explanations rather than adding jargon. Define the term once in README.
Updates the matching FlaUI literal assertions.

**D. Bulk driver/queue export.** Add `--all` to `spoolsmith copy`
(`cmd/spoolsmith/bundlecmd.go`'s `runClone`) rather than a new command. With
`--all`, every *copyable* queue (the same RAW/TCP-9100/literal-IP rule
already enforced by `InstalledQueue.Copyable()` and used by `printers
--copyable`) is bundled in one run into an output directory; non-copyable
queues are skipped and reported with their existing `CopyBlockedReason()`
text, not treated as a failure. This is an independent-exports operation,
not transactional: one queue's failure doesn't abort the batch. Exit
non-zero only if zero bundles were written. GUI parity for bulk export is
explicitly deferred and tracked as a gap in `docs/gui-parity.md`, not
silently dropped.

## What this release does not touch

- The confirmation gate, `--yes`/`--plan-hash`, or anything D-0040 governs.
  A wording tension astra noticed there (the README's "no flag skips this"
  line next to a documented `--yes` flag) is flagged to the operator
  separately as a possible documentation/compliance question — out of scope
  here.
- Bundle-verification/local-status/Intune-hashing progress responsiveness
  and richer partial-failure result presentation — astra's own
  recommendation to treat these as a separate increment.
- The driver-payload trust model, catalog resolution, or any OS-mutation
  code path.

## Process

Implement on a feature branch; `go build ./...` / `go vet ./...` / `go test
./... -v -count=1` on Linux for the cross-platform packages (the
`_windows.go` GUI files and the FlaUI `.cs` tests need a Windows target).
Dispatch astra for a second read-only adversarial pass over the diff;
reproduce every confirmed finding against source before accepting it, per
this repo's standing `STD-001` discipline. Verify the GUI changes on real
Windows hardware before release. Log the round in `docs/dev-process.md` and
publish `releases/v0.7.3.md`.
