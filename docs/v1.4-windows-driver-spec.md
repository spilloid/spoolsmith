# v1.4 — Windows-managed printer setup by IP

Operator direction, 2026-10-01: keep Windows-managed setup by IP in the v1.4
feature stack, alongside USB copies and WSD conversion. The operator also
directed adherence to the adjacent corporate-strategy repository.

## Contract

An operator can enter a literal printer IP, discover its IPP endpoint, save a
reusable `.ssb`, and review installation using Windows' inbox IPP class driver.
The CLI and desktop use the same discovery/profile/install implementation.
Explicit installed-driver selection remains available for RAW TCP/IP printers.
Windows owns class-driver installation and any Windows-managed driver servicing.
This feature does not claim arbitrary OEM driver acquisition from Windows Update.

Discovery reads printer attributes; it cannot install drivers or create queues.
Installation retains the existing elevation, reviewed-plan binding, and explicit
confirmation gates. Reapplication verifies the queue actually present in Windows.
An existing conflicting queue is never renamed, repointed, or removed implicitly.
Failed verification removes only a queue created by that operation and reports
cleanup failure. Status and removal must use the same endpoint verification.

Windows may expose a modern IPP connection through a WSD-named port. Accepting
that monitor name alone is insufficient: inspect Windows' connection data and
verify the actual IPP URL and protocol. A matching model or reachable device
alone cannot establish the configured queue endpoint.

Read `../corporate-strategy/decisions/DECISION_LOG.md` D-0040/D-0041/D-0042,
`state/products/SpoolSmith.md`, `board/README.md`, and STD-001. D-0040 permits

beyond the original catalog families. This work continues those paths under
the operator's current direction. No board vote or general product authorization
is asserted. The product state explicitly says it is stale; current capabilities
are established by this repository and its validation evidence.

## Acceptance evidence

- IP discovery rejects unreachable/non-IPP printers, unsafe/nonliteral endpoints,
  and conflicting identity; it does not silently choose an OEM RAW driver.
- CLI/desktop expose Windows-managed setup without requiring an installed driver.
- Real Windows queue creation, reapplication, status, and cleanup are verified.
- IPP endpoint mismatches and opaque/unverifiable connections fail closed.
- Source-machine preparation is explicitly gated and restores queue settings,
  drivers, default selection, and a working device port; persistent backups remain.
- Unit/PowerShell tests cover endpoint verification and existing-queue conflicts;
  Windows build/vet/full Go suite and relevant GUI checks pass before release.

The preceding hardware failures and source restoration are recorded in
`validation/2026-10-01-wsd-conversion.md`. Clean-target driver setup, cross-PC
apply, and physical printing must be reported separately from same-PC checks.
