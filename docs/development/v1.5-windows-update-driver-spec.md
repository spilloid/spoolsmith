# v1.5 — Windows-supplied native driver for IPP setups

Operator direction, 2026-10-02: one place to type a printer's IP and get a working
mapping with the best driver Windows can supply, "known, or pulled down smartly, but
usually just works", without a vendor OEM installer. Windows keeps moving its own Add
Printer menus, so SpoolSmith is the stable place for it. The lookup is **silent** (part
of the confirmed apply, not a separate opt-in) because it is core behaviour. The operator
authorized the work on the condition that it follows the corporate-strategy standards and
is filed back as a motion (`corporate-strategy/board/meetings/2026-10-02-spoolsmith-v1-5-native-driver/`).

## Contract

An IPP plan (Windows automatic setup by IP, or a WSD queue converted to its verified IPP
endpoint) now ends with one more step after the queue is created and verified:

1. Windows creates the queue with `Add-Printer -IppURL`, as in v1.4 (class driver, endpoint
   verified, new queue removed if verification fails).
2. **Native driver step**, best effort. In order, and stopping at the first hit:
   a. a driver already registered whose name equals the printer's reported model;
   b. `Add-PrinterDriver -Name <model>` (registers a driver Windows already has);
   c. a Windows Update driver search for exactly one printer-class update whose
      `DriverModel` equals the model; Windows downloads and installs it, then (b) again.
3. If a driver is found, the queue is switched with `Set-Printer -DriverName`. The IPP
   endpoint is verified **before and after** the switch against the reviewed URL; if the
   post-switch check fails, the class driver is put back.

"Equals the model" means equal after dropping everything except ASCII letters and digits and
lower-casing, with exactly one candidate. The same rule runs in PowerShell
(`Get-SpoolSmithNorm`) and Go (`normalizeDriverName`) so the apply and `status` agree. A
loosely related OEM driver is never chosen on a guess; a model with no ASCII letters or
digits gets no native step.

## Never fails the install

The queue created in step 1 already works. Every outcome of the native step is one marker line
(`SPOOLSMITH-NATIVE-DRIVER: applied|in-use|skipped ...`), the command always exits 0, a Go-side
error or crash is reported as "skipped", and the step has a 5-minute bound (Windows Update calls
are synchronous). The review sheet and CLI say what happened ("Native driver: ..."); the desktop
shows it as a skipped/done line, never a failure. The single exception: if the step switched the
driver, the endpoint then failed verification, **and** restoring the class driver failed, the
outcome is `attention` and the operation reports an error so the operator reviews the queue.

## What it does not do

- It does not download anything itself, run an installer, or touch drivers it did not just
  register. It never removes a driver, queue or port, never creates a port, never repoints
  a queue (D-0040 boundary: Windows' own `Add-PrinterDriver` / Windows Update resolution only).
- Elevation, reviewed-plan binding and the single explicit confirmation are unchanged. The plan
  shows the step and the model it will look up; `--offline` plans have no live identity and
  skip it.
- Windows Update uses the machine's configured update source. On a WSUS-managed PC it finds
  only what that server offers, then the class driver stays. SpoolSmith does not override the
  source.
- RAW TCP/IP plans (OEM driver already chosen: from a captured profile, a bundle, or an existing
  RAW mapping at the same IP) are not touched.

## Reapply and status

An existing queue is accepted when its driver is the class driver **or** the driver named for the
printer's reported model, and its IPP endpoint verifies. `status` accepts the model-named driver
only with a verified IPP endpoint. Any other driver is still refused ("Windows selected a
different driver"), and a queue is never repointed or renamed implicitly.

## Acceptance evidence

- Unit tests: plan shape, never-fails behaviour, marker parsing, status/reapply driver rule,
  Unicode/empty-model handling, time bound, failed-restore escalation.
- PowerShell harness tests run the real generated command against stubbed cmdlets: upgrade
  from a registered driver and from `Add-PrinterDriver`, quiet skip, restore after failed
  verification, no switch when the endpoint moved during the search, failed restore escalates.
- **Not yet verified on hardware:** a real Windows Update download of an OEM printer driver and a
  real `Set-Printer` driver switch on a live IPP queue. The 2026-10-02 read-only probe on the
  Brother HL-L2315D PC found the WSD PnP node (`WSDPRINT\BrotherHL-L2315D_ser232A`) but no pending
  Windows Update driver, so whether Windows Update offers this model at all is unknown.
  `scripts/validate-printer-release.ps1` (elevated) is the place to record it; until then the
  native step is expected to skip and keep the class driver for printers Windows has no driver for.
- Review: Codex `gpt-6-sol`/high adversarial review of the diff (STD-001); findings and
  dispositions are recorded in `dev-process.md`.
