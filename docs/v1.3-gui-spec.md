# v1.3 desktop spec — "Double-click to install"

Operator decision, 2026-09-24: the desktop is reorganized around its one job —
take printers off this PC, put them on that one — instead of mirroring the
CLI's command list. The operator approved this pitch wholesale, and explicitly
asked for file association, file drag-and-drop, file copy and file paste.

Nothing in the apply engine, plan, plan hash, trust model or confirmation rule
changes. Every change here is a new view over the same shared Go workflow the
desktop already calls. Exactly one explicit confirmation of the shown plan
before any mutation, always.

## What is wrong today (the reasons, so trade-offs go the right way)

- **Review and apply is a page with nothing on it.** It can be clicked into
  cold: grey box, three disabled buttons. Reviewing is a step, not a place.
- **Every screen is a transcript.** Read-only grey TextEdits carry the primary
  content; the printer list is `name — port — driver` strings in a ListBox,
  cut off behind a horizontal scrollbar.
- **Disabled buttons everywhere.** Add a printer shows 3 of 7 disabled.
- **The footer tells you to go away:** "close the app and choose Run as
  administrator."
- **Half the sidebar is occasional-use** (Intune, Inspect, Driver catalog,
  Action log) at equal weight with the main job.
- **Layout shifts between pages** — the sidebar's left edge and the content
  column move between screenshots.

## The design

### 1. The apply sheet (the headline)

One sheet shows one printer file (or one member of a set) and applies it. It
is reached from every "way in": double-click in Explorer (file association),
drag onto the window, paste (Ctrl+V), Open a printer file..., a scan result,
a saved setup. It replaces the Review and apply page as a destination.

```
┌───────────────────────────────────────────────────────┐
│  Accounting Sharp                    from FRONTDESK-01 │
│  10.10.30.11 · SHARP BP-70C31 PCL6 · driver included   │
│                                                        │
│  ✓ Create port 10.10.30.11                             │
│  ✓ Install driver (signed by SHARP Corporation)        │
│  ✓ Trust driver publisher (thumbprint …)               │
│  ✓ Create queue "Accounting Sharp"                     │
│                                                        │
│  Details ▾   More options ▾               [ 🛡 Install ]│
└───────────────────────────────────────────────────────┘
```

- Header: printer name large; one secondary line with address · driver ·
  driver included / settings only; source PC and captured date when known.
- Body: the plan's steps as a checklist of plain sentences derived from the
  existing plan structure (no new plan semantics). Steps that are no-ops
  ("already present") are shown muted, not hidden. Warnings (offline fallback,
  unconfirmed provenance, settings-only reason) get their own clearly marked
  lines above the steps.
- **Details ▾** expands the existing full plan text / JSON (what "Full plan
  details" shows today), with Copy.
- **More options ▾** holds what Review → More options holds today (update an
  existing queue, offline setup, etc.). Changing an option recomputes the
  preview.
- The preview is computed automatically when the sheet opens (no "Preview
  changes" button). While it computes, show a clear in-progress state; never a
  dead grey box.
- Primary button: **Install** (or **Update** / **Remove** / **Change address**
  for those flows — the sheet is reused by This PC's Remove printer and Change
  address, which today route through the Review page). Pressing it still shows
  the existing native confirmation of the shown plan; execution stays bound to
  the reviewed plan hash and re-checks state, exactly as today.
- When not elevated: the primary button carries the UAC shield
  (`BCM_SETSHIELD`) and reads **Install as administrator…**. See §6.
- After execution, the sheet becomes the result: ✓/✕ per step, final
  verification, and a **Copy notes for the ticket** button (§7). Primary
  button becomes **Done**.
- For a set (`.zip`): the sheet first shows the member list (name, address,
  driver, driver included) with per-member **Review** (each member still gets
  its own plan and its own confirmation — a set never widens one confirmation
  to several printers). "Apply all" is NOT added unless it walks each member's
  own sheet and confirmation in turn; if you add it, it must be exactly that.

Implementation latitude: the sheet may be a modal Dialog or an in-window page
that replaces the content area with a Back affordance — choose whichever gives
the cleanest code and reliable UI Automation. It must be reachable with the
keyboard only, with sensible default/cancel buttons.

### 2. This PC is the home screen, as a real table

- Replace the printer ListBox + grey details TextEdit with a `walk.TableView`
  (columns: Name, Address, Driver, and a short state column such as
  "Can copy" / "Settings only" / reason). Small per-row icon if cheap.
- Printers SpoolSmith cannot copy (non-TCP/IP ports: OneNote, Print to PDF…)
  are not interleaved with real ones: they sort to the bottom greyed, or
  collapse behind one line "2 printers can't be copied — why?". Their reason
  remains available (tooltip, details pane, or the why link).
- Multi-select. The copy button's text tracks selection: **Copy 1 printer…** /
  **Copy 3 printers…** (1 → a `.ssb`, several → a set `.zip`, reusing the
  existing single-copy and `bundle.CreateAll` batch paths). This replaces the
  separate "Copy all printers..." button; Ctrl+A selects all copyable rows.
- **Change address…** and **Remove printer…** are secondary, enabled only for a
  single copyable selection (or hidden when not applicable) and open the sheet.
- A compact details area for the selected printer is fine, but not a grey
  read-only TextEdit.

### 3. Files in and out (operator asked for all four)

- **File association.** `.ssb` opens in SpoolSmith. Per-user only
  (`HKCU\Software\Classes`: ProgID `SpoolSmith.PrinterFile`, `DefaultIcon` =
  the exe's icon, `shell\open\command` = `"<exe path>" "%1"`), then
  `SHChangeNotify(SHCNE_ASSOCCHANGED)`. No admin needed. Offered, not silent:
  on first run (and not again after a choice) a small non-modal banner/infobar
  "Open .ssb printer files with SpoolSmith? [Set up] [Not now]", plus a
  permanent toggle under More ▾ → **Open .ssb files with SpoolSmith** that can
  register and unregister. Because the app is portable, if the registered
  command points at a different exe path than the running one, offer to
  update it. Do not associate `.zip`.
- **Command line.** `spoolsmith-gui.exe <file.ssb|set.zip> [...]` starts the
  app and opens the sheet for that file. Multiple files: open the first; a set
  zip opens the member list.
- **Single instance.** Double-clicking a second `.ssb` while SpoolSmith is
  running forwards the path to the running window (named mutex + a
  `WM_COPYDATA` to the existing main window found by a unique window
  class/title property, or equivalent) and brings it to the front, instead of
  opening a second app. Keep this simple and robust; if it fails, fall back to
  opening a new instance.
- **Drag-and-drop in.** Dropping `.ssb` or set `.zip` files anywhere on the
  main window opens the sheet (walk exposes `DropFiles` / `WS_EX_ACCEPTFILES`).
  Non-printer files get a clear one-line refusal. Dispatch on content
  (`bundle.IsSet` etc.), as elsewhere.
- **Copy out (Ctrl+C / right-click → Copy).** With printers selected in This
  PC, Ctrl+C creates the `.ssb` file(s) (same as Copy N printers, same driver
  preference and settings-only fallback with reason) into a per-operation
  folder under `%TEMP%\SpoolSmith\clipboard\`, and puts them on the clipboard
  as `CF_HDROP` (plus `Preferred DropEffect` = copy) so the operator can paste
  them into Explorer, a network share, a Teams/email window. Several selected →
  individual `.ssb` files is fine (the operator can zip); show progress since
  creating a bundle probes the printer. Clean up stale clipboard folders older
  than a day on startup.
- **Paste in (Ctrl+V).** With `.ssb`/`.zip` files on the clipboard (copied in
  Explorer), Ctrl+V in the main window opens the sheet, same as drop.
- **Drag out** of the table into Explorer is a stretch goal: only if it can be
  done robustly with OLE `DoDragDrop` from walk without destabilizing the app.
  Skip it rather than ship it flaky.

### 4. Add a printer

- Scans the connected subnet automatically when the page is first shown (the
  app already discovers the subnet at startup — reuse it). The CIDR/IP field
  is secondary: a "Scan a different network or IP…" affordance.
- Results are a TableView (address, model/identity, confidence), not a
  ListBox of strings. Activating a row goes to the existing setup/settings
  flow and then the sheet.
- "Open a printer file…" and "Open a saved setup…" stay, plus a visible hint
  that files can be dropped or pasted anywhere.
- No disabled buttons for "nothing selected yet": row activation and a single
  "Use this printer" that appears/enables with selection is fine, but the
  page should not open with a row of dead buttons.

### 5. Sidebar and layout

- Sidebar: **This PC**, **Add a printer**. Nothing else at top level.
- A **More ▾** button at the bottom of the sidebar opens a menu: Intune
  package, Inspect a printer file, Driver catalog, Action log, Saved setups
  (if it fits there), Open .ssb files with SpoolSmith (toggle), About/version.
  Those destinations keep working exactly as today — as pages reachable from
  the menu, or dialogs; don't rewrite their internals.
- Review and apply is removed from the sidebar.
- Fixed sidebar width and fixed content margins on every page: the sidebar's
  left edge and the content column must not move between pages. Keep the
  brand header, Segoe UI, native look. No dark mode.
- Every screen has exactly one visually primary action. Hide actions that
  can't apply rather than showing them disabled, where that doesn't hurt
  discoverability.

### 6. Elevation (operator-approved change to "does not self-elevate")

The D-0040 trust model says SpoolSmith does not self-elevate. The operator
approved replacing the "close the app and choose Run as administrator" footer
with an operator-clicked UAC relaunch. Bounds, all required:

- Only ever triggered by the operator pressing a shield button. Never
  automatic, never on startup, never without the UAC consent prompt.
- Mechanism: `ShellExecuteEx` with verb `runas` on the running exe, passing
  the file being applied (and a flag telling the new instance to open it).
  The unelevated instance exits once the elevated one starts (or stays if the
  operator declines UAC — then nothing changes and the sheet says so).
- The elevated instance recomputes the preview and still requires the normal
  single confirmation of the plan it shows. No plan, hash or confirmation is
  carried across the relaunch as pre-approved.
- The CLI is unchanged: it still fails closed when not elevated.
- Record this as an operator update in CLAUDE.md (dated 2026-09-24) next to
  the trust model, and adjust the trust-model bullet's wording accordingly.
- Remove the footer nag. Non-elevated state is expressed on the shield
  buttons, and on This PC as the reason copies are settings-only.

### 7. Copy notes for the ticket

After any apply / update / change address / remove, the result sheet offers
**Copy notes for the ticket**, putting plain text like this on the clipboard:

```
SpoolSmith 1.3.0 — printer setup on PC-NAME, 2026-09-24 14:02
Printer: Accounting Sharp
Address: 10.10.30.11
Driver: SHARP BP-70C31 PCL6 (included in printer file)
- Driver publisher trusted: SHARP Corporation (thumbprint …)
- Driver package staged
- TCP/IP port created
- Printer queue created
- Final configuration verified
Result: Successful
```

Generate it from the execution result structure with a pure, unit-tested
function (no GUI dependency), including failure cases (which step failed and
Windows' reason).

## Tests and verification (required)

- Pure Go logic (plan → checklist lines, notes text, argument parsing,
  association command building, clipboard-folder naming/cleanup policy) lives
  in non-`_windows` files where possible with unit tests.
- `go build ./... && go vet ./... && go test ./...` pass. Also
  `GOOS=linux go build ./...` / vet still pass (main_other.go etc.).
- Update the FlaUI suite in `test/gui/SpoolSmithGui.Tests` for the new
  navigation (sidebar has two items + More), the TableView, the sheet, and
  add tests for: launching with a `.ssb` argument opens the sheet; the
  sheet's Details expand; More menu reaches Intune/Inspect/Catalog/Log; no
  horizontal truncation (TruncationTests). Keep AutomationIds / accessible
  names stable and explicit for everything new.
- Update `SiteScreenshots.cs` so it captures: This PC (table), the apply
  sheet for a sample `.ssb` (use a fixture/example bundle — e.g.
  `examples/intune/accounting.ssb` — with offline preview so it works on a
  hosted runner), the set member list, Add a printer, and the More menu
  destinations it already captured.
- Docs: `docs/gui-parity.md` desktop column, README desktop section,
  `docs/index.html` gallery captions (brand-neutral per the positioning rule:
  tested with HP and Sharp; any standard Windows driver), roadmap "Known
  behavior" entry for Desktop Inspect not listing a set's printers (fixed if
  the sheet's set list covers it).
- Do not bump VERSION or write release notes; that is a separate step.
