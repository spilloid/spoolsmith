How it works

One command finds it. One decision installs it.

SpoolSmith fingerprints a printer over the network, resolves it against a small family-based catalog, and hands you a plan you can actually read — not a wizard full of dropdowns, and never a silent install.

Automatic detection

SNMP, HTTP, and PJL fingerprinting run on their own — no manual fields to fill in for every device you check.

A plan, not a guess

Before anything happens, SpoolSmith shows the exact driver, the exact port, and the exact commands it's about to run. You approve it, or you don't.

Fails closed on ambiguity

If the evidence doesn't clearly point to one supported printer, SpoolSmith says so and stops. It never installs its best guess.

A catalog, not a database

Printer identity resolves through families — one HP entry covers a whole product line — instead of a table that grows one row per model forever.

Scriptable by design

Every command's output is clean JSON on stdout. Prompts and summaries live on stderr, so nothing gets tangled in a pipeline.

Reversible

uninstall takes back exactly what install set up — same printer, same port, same discipline.

Not a wizard. Not an RMM.

SpoolSmith does one job — get the right driver onto the right printer, on your say-so — and is built to structurally not become anything more than that.

  • No credential handling of any kind
  • No remote shell, no arbitrary command execution
  • No scheduled or unattended installs
  • No downloading a driver installer from the internet on its own

The one rule that doesn't move

No install — none, under any flag, including the ones meant for scripting — happens without SpoolSmith showing you the full plan and getting one explicit yes first.

  • Uses only Windows' own printer-management commands
  • Verifies elevation and driver presence before showing a plan
  • Relies on Windows' own signature checks — no custom trust logic

Prefer the terminal?

Everything SpoolSmith does is one command away — detection, catalog lookups, install, and a dry run that touches nothing. 

# Point it at a printer
spoolsmith inspect 192.168.1.64

# See the plan, touch nothing
spoolsmith install 192.168.1.64 --dry-run

# Review, confirm, install
spoolsmith install 192.168.1.64

# Undo exactly what install set up
spoolsmith uninstall "HP LaserJet Pro M404dn"

Under the hood

One idea, followed all the way through

Every printer resolves the same way — from raw evidence down to a specific, swappable driver package — so adding support for a new model is a catalog entry, not a rewrite.

Observed identifiers → Normalized model → Printer family → Driver package

Honest status

What v0.1.0 actually does today

Worth knowing before you rely on it

  • Two printer families today — HP LaserJet Pro M4xx and Brother HL-L2xxx. Anything else fails closed at detection.
  • Install is built but intentionally inert — the exact internal name Windows registers each OEM driver under hasn't been confirmed on real hardware yet, so install refuses to build a plan until that's verified. That's the actual next milestone, not a missing feature.
  • Windows only, for detection and install both, today. The code already separates platform-specific behavior behind a narrow interface — extending it is a real future item, not a rewrite.
