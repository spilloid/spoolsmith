# v1.3.0 desktop redesign validation

Date: September 24, 2026. Hosts: the operator's Windows 11 x64 workstation, and
the hosted Windows runner used by the Desktop validation workflow (elevated).

## Scope

The desktop redesign in `docs/v1.3-gui-spec.md`: the apply sheet replacing the
Review and apply page, This PC as a multi-select table, the two-page sidebar
with More, printer files arriving by `.ssb` association, command line, drag and
drop, Ctrl+V and forwarding to an open window, Ctrl+C to the clipboard, the
operator-clicked elevated relaunch, copy notes for the ticket, removal of the
driver catalog from the desktop, and pending-deprecation notices on the
catalog-driven CLI commands. The apply engine, plan, plan hash and single
confirmation are unchanged.

## Checks completed

- `go build ./...`, `go vet ./...` and `go test ./...` on Windows; `GOOS=linux`
  build and vet. New unit tests cover the plan checklist (each line bound to the
  command that actually ran), ticket notes, the elevated hand-over argument
  (re-validated, never an approval), argument quoting, the association command,
  clipboard folder expiry, printer-file filtering, `bundle.AllOptions.Only`, and
  the CLI deprecation notices (stderr only; stdout and JSON unchanged).
- Clipboard round trip in Explorer's file-drop format (CF_HDROP), including a
  non-ASCII file name. Runs in CI only, because it replaces the clipboard.
- Desktop validation workflow: 34 of 34 FlaUI tests passed on the final commit,
  including new tests for the sidebar and More menu, a printer file on the
  command line opening the sheet, leaving the sheet, pasting a file copied in
  Explorer, saved setups opening the sheet for each operation, and captions
  fitting at default and minimum window size on every page and the sheet.
- The first desktop runs found real defects, fixed before release: More options
  could not be opened while a preview was being prepared; controls declared
  hidden were shown until first toggled; loading the sheet's options started a
  preview with only some of them applied; status labels were cut short; and the
  main window opened several screens tall (also true of v1.2.0).
- The new paste test found that no keyboard shortcut had ever fired: walk only
  consults shortcut actions when the focused control is itself a form. Ctrl+C,
  Ctrl+V and Ctrl+A are now handled for the whole main window.

## Operator checks on real hardware

On the operator's workstation, not elevated unless noted, with the preview build:

- Ctrl+C on This PC produced a 9.5 MB `.ssb` of a network printer with its
  driver included; Ctrl+V of printer files opened the apply sheet. The operator
  reported both working.
- The Intune wizard produced two complete packages for the example printer,
  including the `.intunewin` from Microsoft's Content Prep tool.
- The apply sheet opened from a printer file on the command line, showed the
  plan and the shield button, and did not change Windows.

## Not yet exercised

- Applying a copied printer on a second, clean PC through the elevated relaunch
  (accepting and declining the UAC prompt) and printing a page.
- Double-clicking a `.ssb` through the association, and dropping a file onto the
  exe from Explorer, on real hardware (the command-line path they use is tested).
- Forwarding a second double-click to an elevated window.
