# v1.1.0 UX and release validation

Date: September 23, 2026. Host: Windows x64.

## Scope

Reviewed the changes since v1.0.1: automatic offline fallback, copying an
unreachable printer, unified .ssb saved printers and library sets (settings-only
at first; `.zip` printer sets carrying drivers later the same day, see below),
desktop permission/error wording, Intune packaging, the product website, and
the desktop navigation redesign.

Two additional release blockers were reproduced and corrected:

- A canceled install probe could become offline setup. Regression cases now
  cover cancellation before probing, during the first probe, during the identity
  retry, and a collector returning cancellation. No mutation may occur.
- Intune exported bare JSON after the CLI stopped reading that format. It now
  exports a settings-only profile.ssb, stages that file, and uses it for status,
  removal and installation without an embedded driver. A v2 endpoint marker
  rejects incompatible older binaries. A regression opens exported profiles
  with the bundle reader and the actual exported CLI, with and without drivers.

## Desktop navigation redesign

The main window's tab strip, and the second strip nested under its Tools tab,
were replaced by a sidebar: This PC, Add a printer, Review and apply, then a
Tools group with Intune package, Inspect, Driver catalog and Action log. The
Intune wizard's two tabs became two steps; the review step is reachable only
by validating, and going back discards the review. Every dialog shares the main
window's header band. No new mutation surface: the same handlers run, and the
one plan confirmation is unchanged.

- The sidebar is a native owner-drawn list created with `LBS_HASSTRINGS`, so
  UI Automation and screen readers get each page's name. The FlaUI suite
  navigates by those names and asserts that no tab control remains.
- Pages and wizard steps switch with `ShowWindow` directly and relayout the
  whole window. walk's `SetVisible` skips the call while an ancestor is
  hidden, which at first stacked every page into one column and later left
  shifting gutters around the sidebar. Both were caught in screenshots and fixed.
- An adversarial review of the GUI diff found, and this release fixes: leaving
  the Intune review while Microsoft's Content Prep Tool ran could let Close
  skip stopping it; sidebar rows were not re-measured on a DPI change and
  could exceed Win32's 255-pixel row limit at very high scaling; focus could
  stay on a control in a page that was just hidden; Enter could trigger a
  disabled default button in Saved setups; dialog header bands ignored high
  contrast. The sidebar draws with system colors in high contrast.
- The Intune Advanced panel uses the same direct show/hide, which removed the
  intermittent advanced-control timeout seen earlier in this round; the Intune
  tests then passed three consecutive isolated runs.
- Minimum window size is 960x640 (default 1060x720), up from 820x620, to fit
  the sidebar. Caption-fit tests pass at both sizes on every page.

Known cosmetic issue: on Add a printer the sidebar and page sit slightly inset
from the window edges (walk does not treat that page as horizontally greedy);
other pages span the window.

Not yet validated for the redesign: real high-contrast, 150%+ multi-monitor
DPI moves and Narrator walkthroughs. These stay on the roadmap's accessibility
priorities.

## Printer sets and drivers by default (later, same day)

By operator direction (CLAUDE.md, "Operator update, 2026-09-23"), `.ssb` is the
one printer file and a printer set is a plain `.zip` of top-level `.ssb`
entries: no `set.json` index, note in the zip comment. This replaces the
earlier unreleased set-with-index design from 2026-09-22. `copy --all` now
writes one set instead of a folder; `apply <set.zip>` gives every printer its
own plan and confirmation (`--member` picks one); `bundle inspect` lists a
set's printers; `profile export-all`/`import-all` read and write `.zip` sets
and carry embedded drivers. Copies include the driver whenever it can be
exported and otherwise save settings only with a stated reason;
`--settings-only` opts out and `--include-driver` is a no-op.

Covered by Go tests (`go test ./internal/bundle/... ./internal/profileset/...
./cmd/spoolsmith/... ./internal/intune/...` passed on Windows in this round):

- Set format: write/open/extract round trip without overwriting; a member with
  an embedded driver round-trips byte-identical; a hand-made zip of `.ssb` files
  opens as a set; fail-closed on nested paths, non-`.ssb` entries, unsafe or
  duplicate names, empty or oversized sets; dispatch by content, not extension.
- Copy: the driver is preferred and falls back to settings only when not
  elevated; `--settings-only` never touches the driver store; `copy --all`
  writes one set with mixed outcomes, suffixes colliding names, refuses an
  existing or non-`.zip` path up front, writes nothing when every queue is
  skipped, and writes no set on cancellation; the default name is timestamped.
- Apply: each printer in a set is confirmed on its own, `--yes` still shows
  every plan, `--member` selects one, and `--plan-hash` over a whole set is
  refused without `--member`.
- Transfers: embedded drivers travel verbatim; export requires a `.zip`; a set
  or file changed after review is refused; collisions are checked before
  anything is written.
- Manual spot check: a set made with PowerShell's `Compress-Archive` from the
  example `.ssb` was listed by `bundle inspect`, and `intune build` refused it
  (a package takes one printer's `.ssb`).

After this change the full native FlaUI suite passed (34 tests), covering the
Copy all printers dialog (inventory, set path, cancel without writing) and Saved
setups; the website screenshots were refreshed from the real app. The Printer set
picker opens from a Windows file dialog, which the suite does not drive, so it is
not yet covered by desktop automation. The CLI smoke check above covers a real
set; no set has been applied to real printers or moved between two PCs.

The operator reported testing multiple HP and Sharp network printers with this

## Upgrade and validation boundaries

Existing .ssb bundles remain supported. Older bare-JSON profiles and JSON
library exports are no longer accepted; users must retain originals for
reference and recreate setups through capture or copy. No existing Windows
printer is changed simply by upgrading.

This round did not install/remove real printers, perform a physical two-PC
transfer, print through a transferred driver, or validate a live address change.
Offline behavior is covered by fake-environment regression tests. Broader
hardware, scaling, screen-reader and high-contrast checks remain on the roadmap.
Local status is not evidence of network reachability or physical printing.

Corporate-strategy review is deferred by explicit operator direction: major
feature motions are being filed for downstream review, without processing or
claiming a board decision. Publication uses the existing signed release workflow;
the downloaded release asset must still be checked after publication.
