# v0.2.0 — Reusable printer profiles and working Windows mapping

This is a Windows command-line release. A native desktop GUI is next and is not
included in this build.

- Discover printer candidates on an explicit IPv4 subnet, or start with a known IP.
- Capture one JSON profile per printer and reuse it on another workstation.
- Add, configure, and remove queues with reviewed plans. Matching queues and ports
  remain unchanged on repeated add; repeated removal of an absent queue succeeds.
- Save profile edits with backups. Shared ports and drivers are retained on removal.
- Optionally stage the verified Brother HL-L2315D driver from a local archive,
  checking its pinned hash and Windows signatures before INF staging.
- Use concise terminal output or explicit JSON for scripts.
- Refreshed product site with practical quick-start guides.

## Verified

Brother HL-L2315D discovery, signed driver registration, queue creation, repeated
add with no changes, and an operator-observed physical test print. Automated tests
cover profile validation, identity conflicts, confirmation, idempotency, shared
resources, and staging failures. Windows PowerShell doubles exercise mutation logic.

## Requirements and limits

Run mapping operations in Administrator PowerShell. Most drivers must already be
registered locally; the optional package recipe currently supports only the verified
Brother model on Windows x64. Vendor driver payloads are not bundled or downloaded
automatically. Discovery requires an explicit /24 through /32 IPv4 CIDR.
Direct catalog-based `install <ip>` still requires verified built-in driver names;
use the profile workflow. Live removal/configuration and a clean-machine run of the
new package automation remain unverified. Failures can leave partially staged resources.

See the included README for capture, add, configure, remove, and local-package usage.
