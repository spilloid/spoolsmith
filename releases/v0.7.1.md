# v0.7.1 — A simpler Intune packaging wizard

v0.7.0 shipped Intune packaging on both the CLI and desktop GUI, but every
field was manual — deployment ID, revision, binary hash, output folder. This
release derives sensible defaults from the profile so the common case needs
almost none of that:

- The deployment ID, app display name and description are suggested from the
  printer profile. The CLI binary's SHA-256 is calculated automatically
  instead of requiring a separate step. An unused export folder beside the
  profile is suggested rather than needing to be invented.
- The desktop GUI wizard collapsed from three pages to two, with an
  **Advanced settings** panel for updates, metadata and policy overrides when
  you need them. The CLI wizard offers the same advanced prompts on request;
  `intune build` keeps all its flags as explicit overrides.
- Everything that made packaging trustworthy is unchanged: the CLI binary is
  still verified (PE architecture, Go build identity, endpoint capability
  marker), payload hashes are still pinned and re-verified at export, and
  export still requires a separate, explicit confirmation after review.
  Tenant sign-in and automatic upload/assignment remain out of scope.

This was built by Codex (`gpt-6-astra`, adversarial peer review) in an
isolated worktree, then verified independently — including two rounds of real
Windows hardware testing that caught and fixed two genuine UI-Automation bugs
before anything merged. See
[the validation record](https://github.com/spilloid/spoolsmith/blob/main/docs/validation/2026-09-18-gui-intune-ux-simplification.md).
