# v1.6.0: set up a whole printer set from the desktop

The desktop catches up with `spoolsmith apply set.zip`. Drop a printer set (`.zip`) on
SpoolSmith, double-click it, or open it from **Add a printer**, and it opens one review of
every printer in the set instead of a list you had to work through one at a time.

- **Every printer is checked first.** Each one is previewed against this PC, with no
  changes, and listed with its address, whether it carries its driver, its plan and a tick
  box. A printer that can't be set up, or has nothing to change, is left unticked.
- **The selected printer's steps show under the list**, in the same plain sentences as the
  single-printer sheet. **Details** has each printer's steps with its full plan beneath.
- **One confirmation for the ticked list.** **Set up N printers** names every ticked printer
  and its step count, and asks once. Each printer then runs exactly the steps shown for it;
  a printer whose steps changed since the review is not set up.
- **A tidy result.** The list shows each printer's outcome, the status line reads
  `N set up, N failed, N left alone`, and **Copy summary for the ticket** copies one line per
  printer.
- **Set-wide options.** *Update printers already on this PC* and *Offline setup* apply to the
  whole set and re-check every printer.
- **One damaged printer file doesn't block the rest.** It is listed as one that can't be set
  up, with its reason, as the CLI already did.
- **Administrator rights.** Without them, the shield button reopens SpoolSmith elevated with
  the same printers ticked. The elevated copy checks every printer again before asking.
  **Review only this printer...** still opens one printer on its own sheet.
- Inspect on a set no longer leaves extracted copies in `%TEMP%`.

## What changed in the rules

On the desktop, one confirmation now covers every ticked printer in a set (operator
decision, 2026-11-10). Nothing changes before that confirmation, and each printer is still
bound to the plan you saw. The CLI is unchanged: one confirmation per printer, or `--yes`.

## What is not verified

Setting up a set has run in automated tests (preview, ticking, confirmation text, the
elevated hand-over) but not yet on real printers from a real `copy --all` set. The earlier
gaps stand: a clean second-PC apply with physical output
([#38](https://github.com/spilloid/spoolsmith/issues/38)), uninstall leaving publisher trust
([#37](https://github.com/spilloid/spoolsmith/issues/37)).

## Validation

`go vet ./...` and `go test ./...` pass on Windows 11, and Linux `go vet` is clean. New unit
tests cover preview and result classification, the confirmation text (only ticked, runnable
printers), button captions, the summary and details text, and the set hand-over. A new
desktop test opens a three-file set with one damaged file and checks that two printers are
ready, one can't be set up, the steps panel shows sentences, unticking narrows the button,
and Details lists every printer. The full desktop suite passed 41 of 41.
