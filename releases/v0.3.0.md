# v0.3.0 — A desktop app in front of the same reviewed workflow

This release adds a native Windows desktop app. It is a second way into the
operations v0.2.0 already shipped, not a second implementation of them: the app
calls the same `internal/install` workflow the command line does, so a plan
previewed in the app is the plan the CLI would print.

- Open the app and it scans the network this PC is connected to, detected from
  its connected Wi-Fi or primary Ethernet adapter. Override the subnet, or skip
  discovery with an address you already know.
- A discovered printer that already has saved settings goes straight to its
  reviewed plan. Setting one up with different settings stays one click away.
- Windows driver names no longer have to be typed from memory. An unambiguous
  match between the model the printer reports and the drivers installed on this
  PC is filled in for the operator to confirm; ties and weak matches are left
  empty rather than guessed. Preflight still verifies the driver is registered.
- Saved printers are listed with their address and driver, and can be set up,
  updated, removed, or edited in place with a backup.
- Every change is previewed before it is applied and applied only after the
  shown plan is confirmed. Changing an input invalidates the preview, and the
  shared workflow rejects an execution plan that differs from the reviewed one.
- `spoolsmith drivers` lists exact registered Windows driver names from the CLI.

## Fixed

- Captions containing `&` were consumed as Win32 accelerator prefixes: the
  "Review & apply" tab rendered as "Review  apply", as did the "Save & review"
  button and its label.
- Selecting an operation in code left two mode radio buttons checked at once,
  so the review screen could describe a different operation than the one shown
  as selected.
- The saved-settings editor and the advanced options were both visible on first
  open. Hiding a control while its tab page is hidden is a no-op, because the
  control already reports itself invisible through that ancestor.
- The plan output rendered as one run-on paragraph. Native Windows edit controls
  break lines only on CRLF, and the shared workflow writes LF.
- Closing the window was blocked during a read-only preview, not just during an
  actual change.
- Arriving at the setup screen from discovery left the profile save path empty.

## Verified

Network detection selected the connected adapter's subnet, and a scan of it
listed a Brother HL-L2315D that was then previewed against its saved settings.
27 FlaUI desktop tests drive the real executable: navigation, discovery, profile
selection and handoff, caption layout at both the opening and minimum window
sizes, and that neither optional panel opens unasked. None of them confirm an
install or mutate a Windows printer. Go tests cover the driver suggestion,
network selection, and the shared workflow's changed-plan rejection.

## Requirements and limits

Run as administrator to apply queue changes; finding printers and saving their
settings does not need it. Most drivers must already be registered locally; the
optional package recipe still supports only the verified Brother model on
Windows x64, and vendor payloads are neither bundled nor downloaded. Discovery
takes an explicit /24 through /32 IPv4 CIDR. Live removal and configuration
against real hardware remain unverified, as does a clean-machine run of the
package automation. Failures can leave partially staged resources.

See the included README for the desktop build command and the command-line
capture, add, configure, remove, and local-package usage.
