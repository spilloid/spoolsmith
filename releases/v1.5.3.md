# v1.5.3: the plan names the publisher it trusts, and driver staging is admin-only

A security release. It closes the two items v1.5.1 listed as still open. How printers are
copied, applied and removed is otherwise unchanged.

- **The plan names every publisher it may trust.** For a printer file that carries a driver,
  the plan you confirm now lists each signer `apply` may add to
  `LocalMachine\TrustedPublisher`, by subject and thumbprint, read from the driver's own
  catalog. `apply` trusts only those. A signer the plan didn't name is reported and left for
  Windows to decide. The plan and the output also say that `uninstall` does not remove this
  trust, and give the `certutil -delstore TrustedPublisher <thumbprint>` command that does.
- **Driver files stage only in an administrators-only folder.** The staging folder
  (`%TEMP%\SpoolSmith-bundle-<digest>`, which is `C:\Windows\Temp` under Intune's SYSTEM
  context) is now created in one step with access for SYSTEM and Administrators only. Before,
  a standard user could create that folder first and swap the files before `pnputil` ran.
  A folder that isn't provably administrators-only is never used and never deleted: it is
  renamed to `…untrusted-<n>` and the driver is staged fresh. If a file inside is held open,
  the rename can't happen, and `apply` stops and says so.
- **Previews no longer leave a staging folder.** An unelevated preview (the desktop app
  before *Continue as administrator*, or `--dry-run`) checks the driver in a private folder
  and removes it. The administrator run stages its own copy.

## Upgrading

- Plans for printer files whose driver has a real signed catalog now **fingerprint
  differently** from v1.5.2, because they name the signer. If you approve plans by
  fingerprint in scripts, re-approve them once.
- A staging folder left by v1.5.2 or earlier is moved aside the first time you apply that
  printer file as an administrator. You may delete the `…untrusted-<n>` folders by hand.

## What is not verified

The elevated checks still haven't been run on a clean second PC: the v1.5.1 checklist and a
cross-PC apply with physical output
([#38](https://github.com/spilloid/spoolsmith/issues/38)). Uninstall does not reverse
publisher trust ([#37](https://github.com/spilloid/spoolsmith/issues/37) stays open for that).
The desktop suite's 150% scaling gap ([#33](https://github.com/spilloid/spoolsmith/issues/33))
is unchanged.

## Validation

`gofmt`, `go vet ./...` and `go test ./... -count=1` pass on Windows 11. New tests:
- the folder protection rules (11 security-descriptor cases)
- a user-writable folder, a junction and a held-open file at the staging path
- the catalog signer parser checked against `Get-AuthenticodeSignature` on real Windows
  system catalogs
- a valid signer the plan doesn't name, which is never trusted

The refusal tests fail with the protection check removed. Linux `go vet` is clean. CI passed
on Linux and Windows, including the MSI build and install, upgrade and uninstall jobs.
