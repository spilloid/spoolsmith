# v0.7.0 — Intune packaging from the desktop GUI

`spoolsmith intune build`/`wizard` shipped on the CLI earlier this cycle: local,
reviewable generation of a Win32 app bundle (install/uninstall/detect scripts,
README with the exact commands) for a validated printer profile — no tenant
sign-in, no upload, no OS mutation. This release enables the same wizard from
the desktop GUI (Tools tab → **Build an Intune printer app...**), which had
shipped in source but stayed behind a disabled button pending its own
validation pass.

- The GUI wizard calls the same `internal/intune` `Prepare`/`Export` the CLI
  uses — same output, same trust model, not a second implementation.
- Its fields are now addressable by the desktop test harness, and two new FlaUI
  regression tests cover opening the dialog and the full export happy path
  (profile + CLI binary in, reviewed package out, asserted on disk).
- Tenant sign-in and automatic upload/group-creation/assignment remain
  explicitly out of scope for both the CLI and the GUI — SpoolSmith stays a
  printer deployment enabler, not a tenant-management tool.

Deliberately **not** in this release: the wizard's native file-picker "Browse..."
buttons were not exercised end to end (fields were driven directly), and no
Intune tenant/Company Portal interaction was performed — packaging doesn't
require either.

Validation: Linux and Windows CI passed. A real Windows run (kubert,
`DESKTOP-BBQQE4J`) passed all 3 targeted checks — the two new wizard tests plus
a pre-existing sanity check — launched via an interactive Scheduled Task after
a plain SSH-launched GUI process failed to attach to a visible desktop for UI
Automation (a Windows session-isolation quirk, not an app defect). See [the
validation record](https://github.com/spilloid/spoolsmith/blob/main/docs/validation/2026-09-17-gui-intune-wizard.md).
