# v1.5.2 — `spoolsmith version`, and docs that match the product

A small release. Nothing about how printers are copied, applied or removed has changed.

- **`spoolsmith version`** (or `--version`) prints the build's version: `SpoolSmith v1.5.2`
  in a terminal, `{"version": "v1.5.2"}` when stdout is redirected.
- **A bare `spoolsmith` shows the help** in a terminal instead of a JSON "command is required"
  error. Redirected, it still returns that JSON error with exit code 2, so scripts see no
  change.
- **Docs corrected.** The product site said USB and IPP printers were unsupported (both
  shipped in v1.4) and claimed every brand works, which the Safety guide says hasn't been
  tested. Several pages implied the plan names the driver publisher it may trust; it states
  the rule, not the certificate, and the docs now say so. v1.5.1's still-open items are on
  the Safety page, and the roadmap is current.
- **Clearer wording in the app.** The copy dialog says the other PC confirms the same
  *model* (not "the same one"), `intune build --help` no longer mentions `.json` profiles,
  and the CLI help is tidier.

## What is not verified

The desktop suite ran 39 of 40 at 150% display scaling. The Intune wizard's export never
runs under automation at that scale, on v1.5.1's code too
([#33](https://github.com/spilloid/spoolsmith/issues/33)); a manual export at 150% hasn't
been tried. Everything listed as unverified in v1.5.1 still is.

## Validation

`gofmt`, `go vet ./...` and `go test ./... -count=1` pass on Windows 11, with new tests for
both CLI changes. The product-site checks (`test/site/check.cjs`) pass with no axe
violations at 360, 390, 768 and 1440 pixels. CI passed on Linux and Windows, including the
MSI build and install/upgrade/uninstall jobs.
